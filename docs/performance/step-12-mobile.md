## Mobile baseline

WebKit runs unthrottled. These are simulations, not physical Android/iPhone hardware or a guarantee about every Safari release. No new browser dependency or paid device service is added.

The journey covers profile video playback, touch closing, discovery filters, venue navigation, Back, login and signup form entry without submission, rapid TV scrolling, bounded simultaneous sources/players and release on exit. API writes are suppressed. The first runner used an ambiguous password selector; its partial results are retained and the complete run uses the existing password field ID. An intercepted selector is a harness failure, not a failed authentication feature.

All six initial configurations reproduced a blocked profile-viewer close target. In portrait it was at y=16 through 62 while the demo notice ended at y=47; the notice received the center touch. Landscape WebKit hit the profile title bar. Playback and the preceding discovery/navigation phases worked. This confirmed the earlier Step 4 observation across both browser engines.

The completed baseline passed the portrait workflows and reproduced the close overlap. The landscape runner was corrected to use the visible TV launch control instead of the hidden mobile bottom button. ## Scoped correction

The profile media section's isolated stacking context kept its fixed viewer beneath unrelated page controls. Expose whether its viewer is open, and release that isolation only during the open state. Keep the public viewer below the existing responsive demo-notice inset, using dynamic viewport height; exclude native fullscreen so its previous sizing remains intact. No player is moved, recreated or portaled, and no media card height, crop, design material or closed-profile layout changes. No extra timer, observer, listener, request or dependency is needed.

A disposable browser experiment confirmed the two changes together restore touch closing in Android portrait and WebKit landscape. The production source then receives the same correction. The profile smoke test now requires `tap()` rather than accepting Escape as a substitute. Full automated checks precede release; all six mobile journeys, profile lifecycle, dashboard roles and health checks must pass on the successful deployment. Baseline and exact deployed results are retained in the delivery archive. Physical notch/keyboard behavior, actual cellular radio conditions and live account signup remain explicit device/account-test limits.
